## Conventions

- Auth: a logged-in session cookie (`SUB` @ .weibo.com) is required for `weibo.com`.
- Most `weibo.com` POSTs need header `X-Xsrf-Token` (from the `XSRF-TOKEN` cookie).
- `api.weibo.com/webim/*` uses app-id `source` params (e.g. 209678993).
- `web.im.weibo.com/im/*` is Bayeux (CometD) long-polling, JSON array envelope.
- `M` = method. `Mut` = mutating. `Src` = source (scraper / burp / both).
- Status 400/404 on a probed GET often means required params were placeholders.
- `ok`/`code`/`retcode`/`result` are common response signals; `ok:1` = success.
- Values shown are redacted where long; captured params are from a different account.
- **Live column** verdicts (from `src/live_test.py`, real requests with the logged-in session):
  - `ok` = HTTP 200 + success envelope. `ok_http` = 200 but non-standard envelope.
  - `exists_param_needed` = 400/500: endpoint alive, needs business params (not dead).
  - `dead` = 404: path removed by the server.
  - `blocked` = 403: exists but anti-crawl / source-check blocked our request.
  - `ssl_cert_expired` = `web.im.weibo.com` only: endpoint exists but the bundled CA is expired; reachable from a browser or with an updated CA (see `chat.py`).
  - `mutating_skipped` = POST that changes state; not exercised to protect the account.
  - `error` = request failed (network/TLS other than the CA case).
